# GitHub read-only context

Set `GITHUB_TOKEN` to a fine-grained personal access token on the server. Optionally set `GITHUB_USERNAME` to the account whose assigned issues and requested reviews should appear. With no username, the adapter reads the authenticated account. Restart after changing environment variables. Credentials never appear in browser configuration, response objects, log headers or SQLite. No GitHub writes are implemented: every upstream call passes through Octokit's GET request interface.

Select the appropriate resource owner and repositories when creating the token. Repository Metadata read access supports discovery and mapping verification; add **Issues: read**, **Pull requests: read**, **Actions: read**, and **Contents: read** for their respective contexts. Organization policies may require approval; expired, denied or unapproved tokens produce actual section errors. Repository discovery does not prove access to every section. A token has its own repository/resource-owner scope; TÆSKS does not silently broaden it or use public unauthenticated requests as a substitute.

The current REST API version is pinned to `2026-03-10`. The permission and pagination assumptions were checked against GitHub's official [fine-grained permission reference](https://docs.github.com/en/rest/authentication/permissions-required-for-fine-grained-personal-access-tokens), [API versions](https://docs.github.com/en/rest/about-the-rest-api/api-versions?apiVersion=2026-03-10), [repository endpoints](https://docs.github.com/en/rest/repos/repos), and [search endpoints](https://docs.github.com/en/rest/search/search). Search returns only accessible resources, can be incomplete, and has a maximum of 1,000 results. The interface exposes incompleteness and next-page controls rather than claiming a complete global account inventory.

## Data flow

`src/lib/server/github.ts` owns the server-only Octokit adapter. `GET /api/github` returns browser-safe `GitHubDashboard` contracts. `GET /api/github?repository=owner/repo&section=issues|pulls|actions|commits&page=N` reads one selected section; the endpoint validates the repository and page before contacting GitHub. No arbitrary host or user-provided upstream URL is fetched. `refresh=1` bypasses the server cache. GitHub UI URLs are restricted to HTTPS github.com without credentials or custom ports. Markdown is rendered without raw HTML or remote image loading.

The initial dashboard makes repository discovery plus two actionable searches: assigned open issues and open PRs with requested review for the selected account. It does not fan out across all repositories. Repository discovery follows all pages, deduplicates IDs and has a visible defensive 10,000-entry limit. Each actionable search page contains at most 50 results and offers pages up to GitHub's 1,000-result cap. Inbox and sidebar counts describe the actionable items on the initial loaded page; the Inbox marks available additional pages with `+`. Palette search gathers every genuinely cached dashboard page and repository section/page, including prior contexts after navigating away. Successful data publication/removal changes its subscription snapshot; observer and fetch notifications do not cause an update loop. Canonical repository/pull-number identities merge review/PR duplicates, and results open the actual retained item. The palette explicitly describes loaded scope, additional pages and stale read errors. Unloaded older GitHub activity requires repository pagination or opening GitHub; no eager repository fan-out or unscoped remote search is introduced.

Selecting a repository or opening a mapped Notion project loads open issues, open pull requests, workflow runs and default-branch commits independently. Each section uses explicit next/previous page controls, preserves permission errors separately and caps navigation at 100 pages; older activity remains accessible on GitHub. PRs returned by the issues endpoint are excluded from the issue section, while upstream pagination is retained even if a page contains only PRs.

The 60-second in-memory cache deduplicates concurrent requests and records each section's actual successful read time. A failed later read retains that section's previous data and original timestamp, labels it as stale, and reports a sanitized error/correlation ID. Failed reads are cached briefly to avoid repeated requests until refresh or expiry. The cache holds at most 150 section/page entries. Requests have a 15-second abort deadline, SDK retries and throttling retries are disabled, and malformed successful response bodies are errors. Global Refresh forces all actively displayed GitHub queries upstream, including the current repository pages; invalidating only the browser query would not suffice.

Settings receives the verified dashboard diagnostic. Project repository mappings are persisted locally through `/api/local`, whose server handler validates repository access with `GET /repos/{owner}/{repo}` when the token is configured. The canonical returned name is saved. When GitHub is disabled, a syntactically valid local mapping can be prepared; its access remains unverified until configured. Existing inaccessible mappings are retained and their project context shows the real denial.

## Explicit conversion and stable identity

Item detail shows its source description, state, labels/author/branch, a safe external link and **Create task**. That button opens the shared `TaskComposer`, with the source title preserved verbatim, source identity/URL and a mapped project default. A single-area project supplies its area. Ambiguous or absent mappings require explicit assignment. Save draft remains available. Creation occurs only through the normal Notion task service after confirmation, never on source read, navigation or search. The composer retains confirmed task IDs and recovery warnings until Done.

IDs are `repositoryLower:issue:issueNumber`, `repositoryLower:pull:pullNumber`, `repositoryLower:action:workflowRunId` and `repositoryLower:commit:sha`. Review-search results and repository PR results use the **same PR number identity**: GitHub search's issue database ID differs from the pull-request database ID and cannot safely identify a conversion. This invariant is regression tested. The existing SQLite external/draft conversion ledgers prevent duplicates; source links show **Open linked task** after a successful conversion. Ambiguous multiple project mappings do not choose the first project silently.

## Verification boundary

The existing `.env` now contains configured credentials. The parent performed a read-only authenticated-account probe with HTTP 200; only status/counts were logged. That proves account authentication, not every repository/section permission. This phase's adapter/browser tests use isolated mocks and explicitly empty GitHub/Notion tokens. No live external writes are used. See `VERIFICATION.md` for sanitized live evidence and `RELIABILITY.md` for current safety boundaries.
